# Паралельна кластеризація текстів на PARCS (TF-IDF + сферичний K-Means)

Лабораторна робота з паралельних обчислень: розподілена система **PARCS-python** (Pyro4) на
Google Cloud Platform. Завдання №4 — *обробка текстових даних, кластеризація текстів*.

Автор: Ладіков-Роєв Микола Олександрович, ТК-31, КНУ імені Тараса Шевченка, факультет
комп'ютерних наук та кібернетики.

## Алгоритм

1. **TF-IDF** (на master, послідовно): токени `[a-z]{3,}`, стоп-слова, словник 1000 слів
   (df ≥ 2 і ≤ 50 %), вага `(1 + ln tf) · idf`, L2-нормалізація.
2. **Сферичний K-Means** (K = 20), відстань `d = 1 − 2·x·c + ‖c‖²`, центроїд — нормалізована сума.
3. **Map-Reduce на кожній ітерації**: воркери отримують свій шматок документів (передається
   один раз і кешується на воркері), повертають мітки, лічильники, частинні суми й inertia;
   master складає суми та нормалізує нові центроїди.
4. Для перевірки корректності на master паралельно запускається послідовна версія
   (порівнюються мітки, число ітерацій та inertia).

Код сумісний із Python 2.7 (у контейнері PARCS) і 3.x, лише стандартна бібліотека, файл ASCII-only.

## Структура репозиторію

| Шлях | Опис |
|---|---|
| `solution/kmeans_solver.py` | розв'язок для PARCS (клас `Solver`, `solve()`, worker-метод `assign_chunk`) |
| `tools/make_dataset.py` | генерація вхідних файлів (20 Newsgroups, збільшений корпус, синтетика) |
| `tools/parse_results.py` | збирає виводи PARCS у таблицю та графік прискорення |
| `tools/evaluate.py` | purity та NMI за мітками `.labels` |
| `tools/local_test.py`, `tools/pyro_test.py` | локальні тести без хмари (імітація воркерів / справжній Pyro4) |
| `results/raw/` | сирі виводи PARCS: `output_{5K,25K,50K}_W{1,2,4}.txt` |
| `results/figures/`, `results/summary.json` | графіки та зведені метрики |
| `report/` | звіт (`report.pdf`, `report.docx`) |
| `deploy/gcp_setup.md` | команди розгортання на GCP |

## Як відтворити

```bash
# 1. Дані (потрібен scikit-learn для режиму 20ng-aug)
pip install scikit-learn
python tools/make_dataset.py 20ng-aug 25000 docs_25k.txt

# 2. Локальна перевірка без хмари (3 «воркери»)
PYTHONPATH=solution python tools/local_test.py docs_25k.txt 3

# 3. PARCS: розгорнути кластер (deploy/gcp_setup.md), у веб-інтерфейсі Jobs -> Add:
#    solution = solution/kmeans_solver.py, input = docs_25k.txt, workers = 1 / 2 / 4

# 4. Таблиця результатів і якість
python tools/parse_results.py results/raw/output_*.txt
python tools/evaluate.py results/raw/output_25K_W4.txt docs_25k.txt.labels
```

Перший рядок вхідного файлу може містити конфіг:
`#PARCS k=20 iters=10 tol=0 features=1000 serial=1`.

## Результати (n1-standard-1, 1 vCPU, 10 ітерацій, K = 20)

Час паралельної частини, с; S₁ — прискорення відносно 1 воркера; E = S₁ / p.

| Документів | 1 воркер | 2 воркери | 4 воркери | S₁ (p=4) | E (p=4) |
|---|---|---|---|---|---|
| 5 000 | 5,23 | 3,46 | 2,52 | 2,08 | 0,52 |
| 25 000 | 22,32 | 12,82 | 7,74 | 2,88 | 0,72 |
| 50 000 | 43,04 | 24,23 | 14,66 | 2,94 | 0,73 |

Висновки та застереження:

- Ефективність зростає з обсягом даних: накладні витрати на передачу фіксовані, а обчислення ростуть.
- Прискорення відносно послідовної версії на master (до 3,9×) перевищує p, бо базова версія на master
  повільніша за одного воркера; чесна міра масштабування — S₁.
- В одному запуску (50 000 документів, 4 воркери) 5 міток із 50 000 відрізняються від послідовної версії —
  наслідок неасоціативності додавання чисел із плаваючою комою.
- Кожну конфігурацію запущено по одному разу.

Повний аналіз (закон Амдала, Karp–Flatt, накладні витрати, якість кластерів) — у `report/report.pdf`.
